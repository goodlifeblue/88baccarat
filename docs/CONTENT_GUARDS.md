# 後台內容防呆

所有業務資料表均在 Directus 儲存／發布／刪除前檢查，錯誤會以中文訊息指出欄位，阻擋該次操作。一般草稿可逐步編輯；格式錯誤仍會被擋下。全站設定沒有草稿狀態，儲存時即須完整。

| 功能 | 檢查與操作方式 |
| --- | --- |
| 文章 | 發布須有標題、摘要、內文、分類、合法且不重複的網址、有效發布日期及完整 FAQ。改已發布文章網址仍由既有機制建立 301。 |
| 頁面 | 網址格式、保留路徑、重複網址、模板與分類搭配、摘要、FAQ、區塊格式、卡片、錨點及數量。首頁不能下架、改網址或刪除。已發布頁面先處理引用並下架才能改網址。 |
| 導覽 | 名稱、有效網址或已發布的關聯頁面；不得移除最後一個已發布導覽。 |
| 輪播 | 啟用前選正確圖片／影片，按鈕文字與網址成對，間隔為 2～30 秒。未完成可停用該張輪播。 |
| 品牌設定 | 品牌名稱及連結不可清空；設定資料不可刪除。 |
| 全站設定 | 必要文字、預設圖片、CTA、分類、頁尾與浮動按鈕的格式及完整性；設定資料不可刪除。 |
| 相關文章 | 不能連到自己或不存在的文章。 |
| 首頁區塊 | 標題、類型、錨點、內容與排序檢查；重複選取文章會被阻擋。停用區塊與未發布文章不顯示，移除選取保留文章。詳見 [首頁區塊管理](HOMEPAGE_BLOCKS.md)。 |
| 轉址 | 站內 301、禁止來源重複／指向自己／循環／覆蓋已發布內容，包含批次變更檢查。 |
| 媒體 | 選取檔案時檢查存在與圖片／影片類型；偵測業務資料表內引用的檔案不能刪除，先更換引用。 |

每個業務欄位皆有操作提醒；系統 ID、建立／更新日期及編輯者設為唯讀。重新整理後台可載入最新提醒。浮動按鈕另有前台保護，舊資料不完整時略過該按鈕。

## 圖片上傳大小

每張圖片上限 **5 MB（5 × 1024 × 1024 bytes）**，剛好達上限可上傳。超限時顯示中文錯誤，要求壓縮或降低尺寸；替換超限圖片會保留原圖。既有圖片不回溯刪除，影片不套用圖片上限。依圖片 MIME、常見圖片副檔名及替換前的檔案類型辨識。

檢查位於 `image-upload-limit.mjs`，在 Directus `FilesService.uploadOne` 寫入前執行，涵蓋一般上傳、替換及使用此服務的網址匯入。目前使用固定版本 11.17.3，且未啟用 TUS 分段上傳；升級版本或開啟 TUS 時，必須重新驗證上傳路徑，不可假設新路徑自動受保護。

單元測試：`node --test scripts/image-upload-limit.test.mjs`；本機實際測試：`node scripts/test-image-upload-limit-live.mjs`（會清除測試圖片）。

## 維護

### 文章暫存

新增文章預設為「暫存文章（草稿）」。按右上角儲存即可保存未完成內容；標題、網址、分類、摘要與內文可先留白，之後從文章清單開啟繼續編輯。這是手動儲存，不是自動儲存。草稿不會出現在前台、首頁文章區塊或 RSS。

發布仍須補齊必要欄位、發布日期與 FAQ，格式錯誤仍會被阻擋。空白網址以 null 保存，允許多篇未完成草稿並存；網址唯一性限制保持不變。沿用既有權限，行銷不能發布或修改已儲存的網址；留白網址由管理員於發布前補填。已發布文章請使用內容版本，改回草稿會下架。關聯與刪除保護仍沿用原規則。

套用既有後台：`node directus/configure-content-guards.mjs`，再執行 `docker compose restart directus`。會放寬文章欄位的非空限制，不更動既有內容或權限；重新整理後台即可看到暫存選項。

- 驗證規則：`directus/hooks/redirects/content-validation.mjs`。
- 欄位型別／預設值：`directus/hooks/redirects/field-rules.json`。新增或變更 schema 時需同步此檔並補測試。
- 欄位與功能提示：`directus/content-guard-settings.mjs`。
- 套用提示：`node directus/configure-content-guards.mjs`；`directus:setup` 亦會套用。
- Hook 修改後：`docker compose restart directus`。
- 單元測試：`node --test scripts/content-validation.test.mjs scripts/floating-validation.test.mjs scripts/pages.test.mjs scripts/navigation.test.mjs`。
- 本機實際 API 測試：`node scripts/test-content-guards-live.mjs`，建立測試資料並於結束時清除。

新增功能的交付必須一併包含：欄位提示、儲存驗證、發布條件、引用／刪除影響、合法與錯誤輸入的測試。行銷帳號使用既有非管理員角色；不能透過一般帳號修改資料模型或權限。

檢查涵蓋經 Directus 正常事件流程的操作；直接修改 SQLite、停用擴充套件或使用停用事件的維護程序會繞過檢查。外部網站是否可連線、站外引用及人工直接改資料庫不在驗證範圍。多筆作業仍依 Directus 本身的交易行為執行；資料庫約束是併發操作的最後保護。
